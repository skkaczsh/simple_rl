# 北极星具身智能技术架构蓝图

日期：2026-04-23

状态：已确认设计草案，等待用户审阅书面 spec

来源：`arch.md` 与本轮 brainstorming 讨论。

## 1. 文档定位

本文定义人形机器人北极星具身智能系统的长期技术架构蓝图。它不是单一“第一版需求”，而是两层结构：

1. 长期架构层：定义云端大脑、本地大脑、小脑、whole-body follower、学校系统、Y 形数据流、模型发布机制和学习闭环的目标与边界。
2. 阶段化工程层：把长期蓝图拆成多个验证阶段。每个阶段都有线上仿真验收、线下真实或高保真验证分支、模块范围、接口演进和决策门槛。

本文覆盖机器人本体智能与学校训练系统，不展开完整商业化产品平台。

## 2. 系统目标

北极星架构的目标，是让人形机器人具备本地可执行的具身智能，同时通过独立学校系统持续进化。

核心目标如下：

1. 在没有稳定云连接时，机器人仍能依靠本地大脑、小脑和 whole-body follower 完成常见任务。
2. 本地大脑输出高维语义意图，而不是低层关节命令。
3. 小脑把高维语义意图转化为可执行、可选择、可回退的全身协调光轴。
4. whole-body follower 平滑跟随小脑选择后的中层命令光轴，并维持全身动力学一致性。
5. 学校系统从本地精炼后的高价值经验中持续训练并发布小脑和 follower 的新版本。
6. 本地学习只更新轻量适配器；学校发布共享主模型版本，并通过 gate 和灰度机制替换。
7. 工程验证采用线上仿真主线推进，并在每个线上阶段通过后派生线下真实或高保真验证分支。

## 3. 蓝图范围

本文覆盖：

- 云端大脑：长时认知、全局规划、知识推理、复杂任务拆解、多机器人意图协调。
- 本地大脑：以轻量多模态模型为核心，生成高维语义意图。
- 小脑：generator + selector/gate，生成并选择全身协调光轴。
- whole-body follower：稳定执行层，跟随小脑输出并支持平滑 fallback。
- 学校系统：经验接收、高价值样本池、训练或聚合、评测、版本发布、失败回流。
- Y 形数据流：本地经验精炼、本地轻量适配、学校群体学习。
- 模型版本机制：候选模型注册、影子评估、双模型并行、灰度发布、gate fallback 和审计记录。
- 验证体系：线上仿真主线 + 线下真实或高保真验证分支。

本文暂不覆盖：

- 开放环境安全认证。
- 商业化产品平台。
- 用户系统、权限、计费、运维监控、售后体系。
- 云端大脑直接参与联邦训练。
- 真实机器人作为早期阶段的主线阻塞条件。
- 本地大脑完整安全仲裁框架。
- 大规模商业多机器人运营调度平台。

开放环境安全和产品化能力，应在封闭场景技术验证成熟后再展开。

## 4. 顶层架构

北极星架构由三层机器人思维结构和一个独立学校系统组成。

### 4.1 云端大脑

云端大脑是长时认知和全局规划模块。它不是学校系统，也不是联邦训练平台。

云端大脑负责：

- 理解复杂任务。
- 维护长期知识和全局上下文。
- 执行高层推理和任务拆解。
- 在规划层协调多机器人意图。
- 向本地大脑下发高层计划、任务约束或目标结构。

云端大脑不直接控制机器人关节，也不直接参与学校侧联邦训练。

### 4.2 本地大脑

本地大脑是机器人本体上的轻量多模态智能核心，应以 VLM、VLA、VLN 或相关轻量多模态模型为核心。

本地大脑负责：

- 理解本地场景、任务、对象、语言和视觉输入。
- 整合短期记忆和任务状态。
- 在没有稳定云连接时执行常见任务。
- 向小脑生成高维语义意图。

本地大脑不输出关节目标，也不直接输出完整中层轨迹。它输出的是语义丰富、带约束的意图，例如：

- 目标和子目标结构。
- 期望速度、节奏和紧急程度。
- 力度或用力趋势评估。
- 避让关键点。
- 接触风险和接触偏好。
- 对象约束。
- 空间约束。
- 任务偏好和失败偏好。

当前蓝图把本地大脑定义为多模态模型核心。完整可审计安全状态机或安全仲裁层，延后到封闭场景验证通过后再展开。

### 4.3 小脑

小脑位于本地大脑和 whole-body follower 之间，是运动生成和选择中枢。

小脑有两个核心职责：

- Generator：在隐空间中生成多条可能的全身协调路径方向。
- Selector/gate：对候选光轴评分、混合和选择，同时处理 confidence、dangerous_sig、模型版本 gate 和 fallback。

小脑不是一个小型辅助预测头，而是把语义意图映射为可执行全身运动可能性的结构层。

### 4.4 Whole-Body Follower

whole-body follower 是稳定执行层。它不做复杂语义理解，而是跟随小脑选择后的中层命令光轴，并生成稳定的全身行为。

follower 必须把电机、刚性体、末端、质心、接触点和姿态约束视为同一条全身协调轨迹的不同投影，不能把它们作为互相独立的控制通道优化。

follower 负责：

- 平滑执行。
- 全身动力学一致性。
- 连续 fallback。
- 对 confidence 下降或 dangerous_sig 上升做稳定响应。
- 当 gate 判断退化时进入保守恢复行为。

## 5. 学校系统分离

学校系统与云端大脑分离。

学校系统接收来自本地客户端或仿真客户端的精炼高价值经验，训练、聚合、评测并发布以下模型的新版本：

- 小脑 generator。
- 小脑 selector/gate。
- whole-body follower。
- MoE experts。
- fallback policies。
- 相关 adapter 或校准模块。

学校系统在当前蓝图中不直接训练云端大脑。

学校系统和云端大脑采用弱通信：

- 学校向云端大脑暴露模型版本、能力边界、评测摘要和失败模式摘要。
- 云端大脑据此避免规划超出当前机器人能力边界的任务。
- 云端大脑不在在线执行时直接查询学校 replay buffer，也不控制训练循环。

## 6. Y 形数据流

运行时学习架构采用 Y 形数据流。

机器人或仿真客户端执行任务时，会产生观测、动作、预测误差、任务结果、失败事件、confidence 变化和 dangerous_sig。原始经验不会全量上传，而是在本地先被精炼。

本地精炼包括：

- 筛选高价值片段。
- 压缩轨迹。
- 提取失败模式。
- 标注触发条件。
- 计算 TD 误差、预测误差或任务误差。
- 生成可回放的结构化样本。

精炼后，数据分成两条分支。

### 6.1 本地适配分支

本地客户端只更新轻量适配组件：

- LoRA。
- FiLM。
- Adapter。
- Task tokens。
- 本地校准参数。

共享主模型在本地保持冻结。本地适配用于处理单机差异，包括执行器延迟、负载变化、局部环境习惯、任务风格和短期动态偏差。

### 6.2 学校学习分支

客户端将精炼后的高价值经验上传到学校系统。学校从多个仿真或机器人客户端聚合学习。

学校侧学习重点包括：

- 提升小脑 generator 和 selector/gate。
- 提升 whole-body follower。
- 训练 confidence 与 dangerous_sig 预测。
- 测试 MoE experts 和 fallback policies。
- 在发布前评估候选模型版本。

## 7. 模型版本、Gate 与 Fallback

学校发布新版本时，不应无 gate 地覆盖本地稳定模型。

模型发布流程如下：

1. 本地保留当前稳定模型作为 fallback。
2. 下载并校验新候选模型。
3. 将候选模型注册到本地版本表。
4. 执行回放评估、影子推理、仿真评测或低风险试运行。
5. selector/gate 根据任务类型、场景风险、confidence、dangerous_sig 和模型分歧决定候选模型接管比例。
6. 当 confidence 下降、dangerous_sig 上升、模型分歧扩大或任务失败率升高时，连续退回稳定模型。
7. 记录切换事件、回滚事件、失败原因和 confidence 变化。
8. 将日志回流给学校，用于下一轮训练和评测。

gate 必须支持平滑 fallback，而不是硬切换。selector 的最终输出是 gate 后的结果。

## 8. 小脑光轴接口

selector/gate 的最终输出，是结构化中层命令混合光轴。它至少包含：

- `pose`：身体、关键刚体或末端的目标姿态和姿态趋势。
- `velocity`：整体运动速度、局部末端速度、节奏和时序倾向。
- `torque_pose`：力度倾向、阻抗意图、接触意图和受力姿态。
- `confidence`：可执行性、模型确信度、局部有效性和任务置信度。
- `dangerous_sig`：跌倒、碰撞、过载、不可达、模型分歧和低置信等风险信号。

这些字段不是独立控制通道，而是同一条全身协调光轴的不同投影。

光轴需要支持：

- 全身耦合。
- 平滑 fallback。
- 模型版本 gate。
- 风险感知行为。
- locomotion、manipulation、contact、posture 的协调。
- 可审计的中层命令记录，用于调试和学校训练。

## 9. 从无语义动作序列学习全身光轴

核心研究问题之一，是如何从无语义动作序列中学习全身协调光轴。

在 follower 收敛前，前期训练应尽量保持无语义。训练信号应来自状态、动作、接触、稳定性、能量、预测误差、任务误差和动力学结果，而不是过早把动作贴上“走路”“伸手”“避让”等语义标签。

这样做的目标，是让模型先学习身体本身的连续协调规律，再引入语义边界。

当 whole-body follower 达到高精度可用后，它可以作为以下角色介入小脑训练：

- Teacher。
- MoE expert。
- Candidate generator。
- 稳定可执行样本来源。

蓝图不预设唯一算法路线，最终方案应通过对比和消融确定。

候选学习路径包括：

1. 无语义 latent dynamics 预训练。
   从 state-action rollout 中学习短期动力学、接触变化、姿态趋势和危险先兆。

2. 专家或运动库先验。
   使用 mocap、MPC、手写 controller 或高质量 follower 轨迹建立自然动作分布。

3. RL rollout 扩展。
   在仿真中扩大任务覆盖，学习抗扰动、极端姿态恢复和长尾场景。

4. 高精度 follower teacher。
   使用成熟 follower 把稳定可执行样本蒸馏到小脑 generator 或 selector。

5. MoE experts。
   将不同运动族、风险等级或任务区域拆成多个 expert，由 selector/gate 混合。

6. 真实或高保真片段校准。
   使用线下验证分支收集高价值片段，修正 sim-to-real 或低保真到高保真的偏差。

消融实验应比较：

- 全身协调性。
- 平滑性。
- fallback 连续性。
- 任务成功率。
- 跌倒率。
- dangerous_sig 提前量。
- 新旧模型切换稳定性。
- 上下肢耦合质量。
- 未见任务或未见姿态泛化。
- 学校版本替换后的退化风险。

## 10. 验证结构

验证结构类似二叉树。

- 线上验证是仿真实时闭环主线。
- 线下验证是真实机器人或高保真硬件在环分支。
- 某个线上 Phase 通过后，创建对应线下验证分支。
- 线下分支是否通过，不阻塞线上主线继续推进。
- 线下结果回流为风险、数据、误差模型、失败模式和后续训练输入。

这种结构在保持工程推进速度的同时，为真实世界偏差修正保留通路。

## 11. 学校系统作为横向层

学校系统不是最后一个 Phase，而是从 Phase 1 开始贯穿后续所有阶段的横向架构层。

从 Phase 1 起，每个阶段都应包含最小学校闭环：

- 记录本地或仿真经验。
- 本地精炼高价值片段。
- 上传结构化样本到学校经验池。
- 训练或聚合阶段相关模型。
- 评估候选模型。
- 发布候选版本。
- 通过双模型并行和 gate 验证替换风险。
- 将失败模式和评测结果返回学校。

学校能力随阶段增强：

- Phase 1 学校能力：收集基础运动底座中的跌倒、扰动、速度跟踪、brace 和 fallback 经验。
- Phase 2 学校能力：收集上下肢冲突、reach 失败、姿态保持失败、接触前悬停失败。
- Phase 2.5 学校能力：对单策略、共享 trunk、多头和 MoE whole-body 策略进行对照实验。
- Phase 3 学校能力：训练和评估 generator、selector、confidence、dangerous_sig 与平滑模型切换行为。
- Phase 4 学校能力：收集从语义意图到运动执行之间的失败样本和能力边界。
- 后续学校能力：扩展到更复杂多模态任务、真实或高保真数据、更强联邦策略。

## 12. 阶段化工程路线

### Phase 0：基础设施与统一 ABI

目标：建立仿真环境、机器人模型、共享 schema、模型格式、数据格式和评测流水线。

关键输出：

- 仿真环境与机器人资产基线。
- Observation schema。
- Command schema。
- Action schema。
- Confidence 与 dangerous signal schema。
- 数据记录格式。
- 模型版本元数据格式。
- 基础评测 runner。

Phase 0 应减少后续接口震荡。后续阶段应尽量扩展 ABI，而不是为每个任务重写接口。

### Phase 1：基础运动底座 + 学校最小闭环

目标：验证站立、行走、转向、速度跟踪、抗扰动、brace、stop 和 fallback。

重点：

- 稳定 locomotion。
- 可恢复性。
- 可测量的跌倒率和失败率。
- 第一条学校数据闭环。
- 最小候选模型发布流程。

线上验收以仿真为主。线上通过后可以派生线下验证分支，但线下结果不阻塞 Phase 2。

### Phase 2：全身协调任务 + 学校扩展

目标：在保持运动稳定性的前提下引入上肢任务。

任务包括：

- 行走 + 上肢 reach。
- 避让关键点。
- 姿态保持。
- 接触前悬停。
- 携带姿态。

重点：

- 上下肢耦合。
- 质心和末端协调。
- 接触感知姿态。
- 学校收集协调失败样本。

### Phase 2.5：Whole-Body 统一策略验证

目标：在后续架构继续叠加前，证明 unified whole-body follower 是否成立。

该阶段拆成三个分阶段验收：

1. Phase 2.5-A：单策略覆盖多控制模式。
   站立、行走、转向、reach、carry、avoidance 和 brace 应由同一策略或同一共享 trunk 支撑。

2. Phase 2.5-B：上下肢互不破坏。
   上肢任务执行不应显著破坏步态稳定；下肢扰动时，上肢目标应能维持趋势或平滑降级。

3. Phase 2.5-C：统一 ABI 成立。
   同一套 `obs / command / action / confidence / dangerous_sig` schema 应能承载前面任务，并成为小脑和本地大脑集成基础。

该阶段应对比 unified policy、shared trunk + multi-head、MoE 和更碎片化的 baseline。

### Phase 3：小脑光轴与 Gate

目标：引入小脑 generator、selector/gate、候选光轴、confidence、dangerous_sig 和新旧模型 fallback。

重点：

- 隐空间候选路径生成。
- 最终结构化中层命令光轴输出。
- 平滑 fallback。
- dangerous_sig 预测。
- 模型分歧检测。
- 候选模型 gate 行为。

该阶段学校系统会变得更加核心，因为 gate 质量依赖大量失败和近失败样本。

### Phase 4：本地大脑语义意图闭环

目标：集成轻量多模态本地大脑，验证语义意图到运动执行的闭环。

重点：

- 语义目标生成。
- 速度、力度和避让提示。
- 对象与空间约束。
- intent-to-light-axis 映射。
- 小脑和 follower 向本地大脑反馈能力边界。
- 从语义意图到执行失败的样本回流学校。

当前蓝图中，本地大脑不作为学校主替换目标。学校主要训练和发布小脑 + follower 版本。

## 13. 阶段进入与退出规则

每个 Phase 都应定义：

- 来自前序阶段的输入能力。
- 新增模块。
- 输出接口。
- 线上验收指标。
- 线下分支范围。
- 失败 fallback 行为。
- ABI 影响。
- 学校数据产出。
- 对前序阶段的回归测试。

某个 Phase 只有在线上验收通过后，才能推进到下一线上阶段。线下分支失败不阻塞线上推进，但必须记录为架构风险，并回流到后续训练或阶段修订。

## 14. 关键风险

### 14.1 小脑光轴是否可学

架构依赖从无语义动作序列中学出全身协调光轴。该假设必须通过 latent dynamics、RL rollout、teacher、MoE 和消融实验验证。

### 14.2 统一 Whole-Body Follower 是否成立

如果单策略或共享 trunk 无法覆盖多控制模式，系统可能退回拼接式控制器，从而削弱后续小脑和本地大脑接口的稳定性。

### 14.3 本地大脑语义意图是否过高维

如果语义意图无法稳定映射到小脑光轴，系统可能需要更显式的中间子目标格式、task tokens 或约束编译层。

### 14.4 学校系统是否能带来真实增益

学校系统必须证明高价值经验精炼、聚合、模型发布和 gate 反馈能降低失败率、提升能力，否则只会增加复杂度。

### 14.5 Gate 和 Fallback 是否足够平滑

whole-body 控制中硬切换模型版本是不安全的。confidence、dangerous_sig 和连续混合必须成为核心验收目标。

### 14.6 仿真偏差

线下分支失败不阻塞线上推进，但失败模式必须回流学校。否则线上系统可能持续过拟合仿真。

### 14.7 ABI 稳定性

统一 ABI 是长期扩展基础。如果过早固化，可能限制后续小脑和本地大脑；如果频繁重写，又会破坏阶段连续性。

## 15. 待验证假设

架构依赖以下假设：

- `pose / velocity / torque_pose / confidence / dangerous_sig` 可以作为稳定的小脑到 follower 中层命令结构。
- 电机、刚性体、末端、质心和接触点可以被学习为同一条全身协调光轴的不同投影。
- 本地 adapter-only 更新 + 学校共享主模型替换，能够兼顾个性化和全局进化。
- 学校与云端大脑弱通信，足以支持能力感知规划。
- Phase 2.5 可以证明 unified whole-body follower 比拼接式控制器更适合作为长期底座。
- 线上/线下二叉树验证结构能够保持工程推进速度，同时吸收高保真和真实世界修正。

## 16. 后续计划中的设计决策

以下决策应在后续 implementation plan 或实验设计中明确：

- Phase 0 的 observation、command 和 action schema。
- 第一版 follower 的具体模型结构。
- Phase 2.5 默认候选路线采用单策略、shared trunk + heads、MoE 还是混合 baseline。
- 学校最小闭环的 replay、片段评分和样本上传 schema。
- 候选模型与稳定模型输出的 gate blending 公式。
- Phase 4 使用哪一类轻量多模态本地大脑模型。
- 每个线上 Phase 对应的线下验证装置和可行范围。
